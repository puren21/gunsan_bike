## 확인된 문제와 변경

- 저장 RPC가 도로 전체 행을 응답해 업로드한 GeoJSON을 다시 다운로드했습니다. 기존 RPC/인자/원자적 revision 비교는 유지하고 PostgREST `select=revision,updated_at`으로 응답만 줄였습니다. DB 함수나 테이블을 변경하지 않습니다.
- 변경 없이 저장하거나 편집을 종료해도 전체 업로드·이력 생성·지도 재생성이 발생했습니다. 편집 변경이 없으면 추가 저장 없이 즉시 완료합니다. 이전 서버 버전에 접속한 다른 컴퓨터의 편집 기준을 임의로 앞당기지 않습니다.
- 지도 재생성은 18개씩 브라우저 idle을 기다렸습니다. 저장 후 지도 반영은 최대 128개/8ms 예산으로 처리하고 작업 사이 타이머에 양보합니다. 초기 로딩은 기존 idle 분할 방식을 유지합니다. 비동기 그리기 오류는 Promise를 거부하여 저장 화면이 영구 대기하지 않게 합니다.
- 초기 접속에 정적 기본 도로를 먼저 그리고 나중에 Supabase 전체 도로로 다시 교체했습니다. 공용 원본을 처음부터 읽고, 초기 지도에 이미 표시한 경우 편집기 초기화의 중복 재생성을 생략합니다. 연결 실패 때만 기존 정적 기본 자료를 표시합니다.
- 정적 기본 레이어는 매번 시각 쿼리를 붙이는 대신 HTTP 재검증 캐시를 사용합니다. 읽기 전용 경계와 기존 표시용 정적 GeoJSON은 변경하지 않습니다.
- 저장 중 속성 입력과 편집 도구를 잠가 대기 중 변경이 완료 처리로 지워지는 것을 방지합니다. 백업 준비 / 서버 저장 / 지도 반영 상태를 구분합니다. 서버 응답과 지도 반영이 모두 성공한 뒤 로컬 초안을 정리합니다. 서버 성공 후 지도 실패는 저장 실패와 구분하고 초안/현재 편집을 보존합니다.

## 한계와 운영 전환

실제 편집 계정으로 운영 도로를 저장하는 테스트는 원본 보호를 위해 하지 않았습니다. 전체 업로드/서버 트랜잭션/이력 기록은 유지되므로 네트워크가 느리면 해당 지연은 남습니다. 저장이 몇 초 빨라졌다는 실측 주장은 하지 않습니다. 기존 다중 탭 공유 초안 키 제약도 유지되므로 컴퓨터당 편집 탭 하나를 권장합니다.

운영 전환 전에 모든 컴퓨터의 미저장 작업을 저장 또는 내보낸 뒤 새 버전을 열도록 안내해야 합니다. 배포는 사용자에게 변경 내용과 검증 결과를 안내한 뒤 별도로 진행합니다. 코드를 되돌릴 때 DB 원본·이력·브라우저 초안을 삭제하지 않습니다.
