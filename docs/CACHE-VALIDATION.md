## 1. 도로 버전 확인과 캐시

- `gunsan_bike_datasets` 원본과 기존 `save_gunsan_bike(p_data,p_revision)` 계약 유지. 마이그레이션·캐시의 DB 자동 업로드 없음.
- 방문 시 `revision,updated_at`만 no-store로 확인. 캐시가 없거나 버전이 달라야 data 포함 행 조회. 동일 버전이면 전체 전송 생략.
- 전체 조회 사이 다른 기기가 저장해도 data와 함께 받은 revision으로 편집 기준 설정.
- 초기화 중복 제거, 활성 편집기의 기준 버전 고정, 중복 저장 차단. 저장 성공 후 캐시 무효화하여 다음 방문은 서버 원본을 재조회.
- 서버 버전을 확인하지 못하면 오래된 캐시로 저장을 허용하지 않음. 손상 캐시·미래 schema는 무시. 캐시 용량 부족은 원본 조회를 막지 않음.
- 로그인 키와 v2/v3 초안 형식 유지. 캐시는 별도 `gunsan_bike:dataset-cache-v1` / schema=1에 변환 전 자료를 보관.
- 저장 전에 초안을 기록하며, 충돌·오프라인·인증 실패 시 편집과 초안 유지. 초안 저장 용량 부족 시 RPC 전송 전 중단.
- 복원한 초안은 미저장으로 표시. 버전이 다른 초안은 최신 서버 자료 위에 자동 덮어쓰지 않고 이전 편집본 내보내기로 제공.
- 미저장 속성·도형·입력점 외에 가져오기 대기·저장 진행 중에도 이탈 경고.

## 2. 읽기 전용 경계의 최종 경량화

GitHub 정적 원본 경계 2개와 roads.geojson은 변경하지 않음. 별도 표시용 파일만 생성. 소수 **7자리**로 반올림하여 아주 작은 섬도 보존하고, 모든 지물·속성·좌표 개수·링 개수 유지. 군산 위도에서 반올림 위치 오차 약 **0.008m 미만**. 공유 원본 좌표는 두 파일 전체에서 항상 같은 표시 좌표로 변환됨.

5자리 반올림은 작은 섬 링 붕괴와 자기 교차를 일으킬 수 있어 사용하지 않음. 7자리 결과는 Shapely로 모든 원본/표시용 지물의 도형 유효성을 확인. 단순화·도형 보정·꼭지점 제거 없음. 새 경계가 유효하지 않으면 생성기는 출력 전 중단.

| 파일 | 원본 bytes | 최종 표시용 bytes | 감소 |
|---|---:|---:|---:|
| 시경계 | 7,912,670 | 5,020,743 | 36.5% |
| 동경계 | 9,024,570 | 5,730,568 | 36.5% |

표시용 파일은 콘텐츠 해시 쿼리 + force-cache. 로드 실패 시 기존 정적 원본을 no-cache로 재검증. 경계 저장 API 추가 없음.

재생성 환경: `python3 -m pip install -r scripts/requirements-qa.txt` (Shapely 2.0.7), `python3 scripts/build-boundary-display.py`. index.html의 해시도 자동 갱신. 실행 전후 원본 파일은 동일해야 함.

## 3. 자동 검사

- `node --test tests/*.test.cjs`: **66개 통과 / 실패 0**.
- `node --test tests/local-http.integration.cjs`: **3개 실제 HTTP 시나리오 통과** (상위 묶음 포함 테스트 러너 집계 4개).
- Shapely: 시/동경계 원본·표시용 **모든 지물 유효**. 링 1,713개 보존, 축소된 링 없음, 공유 좌표 일치 검증 통과.
- JS 파일 및 인라인 스크립트 구문, `git diff --check` 통과. 원본 경계·roads.geojson diff 없음.

HTTP 통합 검사는 임시 서버와 실제 SQLite 트랜잭션을 이용하며 운영 Supabase SQL을 실행하지 않음. 기준 main의 기존 클라이언트 소스를 그대로 로드해 새 클라이언트와 동시 저장: 한 요청만 성공, 나머지는 충돌, 거부된 클라이언트의 기준 버전 유지. 오래된 캐시 교체 후 다음 방문은 메타데이터만 전송.

수정 전 main의 전체 검사 46개 중 5개 실패를 재현했으며 이번에 테스트 환경을 바로잡음. 편집 동작을 변경하거나 검사를 생략하지 않음:
- draw/vertex: 현재 동작과 README에 맞춰 사용자의 스냅 설정 유지(켜짐/꺼짐 양쪽) 검사.
- merge: 빠져 있던 테이블·편집 상태 모의 의존성 보완.
- popup: 현재 폭원 명칭 및 길이 소수 1자리 표시 기대값 반영. 클릭한 라인의 속성만 표시하는 검사는 유지.
- vertex drag: 실제 지도 유형·색상·선택 라벨에 필요한 모의 객체 보완. 프레임 기반 미리보기와 최종 도형 반영 검사 유지.

## 4. 실제 브라우저와 지도 검사

테스트 서버는 loopback에만 바인딩하고, 전달하는 cloud-storage.js의 연결 주소를 임시 로컬 DB로 변경. 외부 fetch는 테스트용 가드와 CSP로 차단하며, 서비스 소스의 운영 주소는 바꾸지 않음. 카카오 SDK·타일은 기존 키에 허용된 **http://localhost:8080**에서 그대로 사용. API 키·도메인 설정 변경 없음.

- 서로 다른 원점 `127.0.0.1:8787` / `:8788`에서 브라우저 저장 공간을 분리하고 같은 임시 DB를 편집: A 저장 성공, B 충돌 거부, B 초안 확인.
- A 재접속으로 서버 원본을 읽은 뒤 다음 재접속: 전체 요청 2회 그대로, 메타데이터만 2→3회 증가. [기록](qa-evidence/browser-cache-status.json).
- **실제 지도 편집 UI** 두 탭이 버전 7에서 시작. A 속성 저장 → 8. B 저장 거부 후 비고 입력 유지, 실제 GeoJSON 내보내기로 내용 확인.
- A가 지도 꼭지점을 드래그하고 저장 → 9. 로컬 DB에서 변경된 중간 좌표 및 A 비고 보존 확인. B 재시도는 거부됨.
- 새 탭에서 최신 자료를 읽을 때 기준이 다른 이전 초안의 내보내기 버튼 제공. 내보낸 GeoJSON에 B의 비고와 기존 도형이 남아 있음을 파일 내용으로 확인.
- 실제 카카오 지도에서 동경계 켜기·축소 후 선 표시 확인. 별도 비교 화면에서도 원본/표시용 전체·도심·작은 섬 확인.

[실제 편집 충돌 화면](qa-evidence/actual-editor-conflict.png), [이전 초안 복구](qa-evidence/actual-editor-draft-recovery.png), [실제 지도 경계](qa-evidence/actual-map-boundaries.png), [경계 비교](qa-evidence/boundary-comparison.png), [최종 연습 DB](qa-evidence/actual-editor-server-status.json).

재현: `python3 scripts/local-qa-server.py --ports 8080` 후 `http://localhost:8080/`. 저장 공간 분리 검사는 기본 포트 8787/8788의 `/__qa__/`에서 실행. 원본 실제 DB는 이 도구로 연결할 수 없음. QA 화면과 도구는 일반 사용자 메뉴에 연결되지 않으며 원격 호스트에서는 QA 화면 실행을 거부함.

## 5. 남은 한계와 운영 전환

이후 앱 안 브라우저의 기존 Supabase 로그인에서 관리 접근이 가능해졌음. 실제 저장/auth 함수, 열·제약 조건, RLS 및 쓰기 권한을 읽기 전용으로 확인했고, 같은 PostgreSQL 17.6에 복제한 실제 SQL로 8개 시나리오를 통과함. 원본을 덮어쓰거나 삭제할 수 있는지 확인하기 위해 운영 자료에 쓰기를 시도하지는 않았음. 상세 결과와 검증 범위는 [Supabase 후속 기록](SUPABASE-STORAGE-VALIDATION.md) 참고.

실제 두 물리 컴퓨터·서로 다른 브라우저 엔진, 운영 Supabase HTTPS 저장 요청 및 JWT 발급 전 과정, 서비스 규모 성능은 이번 검사 범위 밖. 기본 읽기/지도 표시와 배포 파일 일치는 PR #1 배포 후 확인함.

같은 브라우저의 여러 탭은 기존 v3 초안 키를 공유함. 한 탭의 후속 저장이 다른 탭의 로컬 초안 키를 교체/삭제할 수 있으므로 **한 컴퓨터에서는 편집 탭 하나만 사용**하고, 충돌한 탭의 작업은 먼저 내보내기 권장. 서로 다른 컴퓨터의 저장 공간은 분리됨. 여러 탭의 장기 초안을 각각 보관하는 기능은 이번 PR에 추가하지 않음. 이탈 경고 분기는 자동 검사로 검증했으며, 브라우저 자동화의 실제 경고 대화상자 표시는 확정하지 않음.

PR #1은 남은 검증 범위를 안내한 뒤 사용자의 명시적 배포 요청으로 운영 전환 완료. 후속 검증 결과로 앱 코드나 운영 DB를 변경하지 않았음. 모든 컴퓨터는 기존 미저장 작업을 내보내거나 저장한 뒤 새 버전을 열도록 안내. 되돌릴 경우 코드만 복원하며 DB 원본과 초안은 삭제하지 않음.
